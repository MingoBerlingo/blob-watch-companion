# Blob Watch desktop simulator

Runs the **actual firmware pages, navigation, timer logic, theme, drawing code,
LVGL port and LVGL 8.3.11 configuration** on desktop. SDL2 replaces the display;
the desktop board adapter replaces USB peripherals, PWM and IMU reads. The RP2040
instruction set is not emulated.

## Build and run (macOS)

```sh
brew install cmake sdl2
cmake -S simulator -B simulator/build -DCMAKE_BUILD_TYPE=Release
cmake --build simulator/build --parallel
./simulator/build/blob_simulator
```

Requires CMake 3.24+, a C/C++17 toolchain, Python 3.8+, and SDL2. On Debian/Ubuntu:
`sudo apt-get install build-essential cmake python3 libsdl2-dev`.
If Homebrew SDL2 is not found, add `-DCMAKE_PREFIX_PATH="$(brew --prefix)"` when
configuring. The first configure downloads a SHA256-pinned LVGL 8.3.11 archive.
For an offline build after `pio run`, use a fresh build directory:

```sh
cmake -S simulator -B simulator/build-offline \
  -DLVGL_SOURCE_DIR="$PWD/.pio/libdeps/waveshare_rp2040_touch_lcd/lvgl"
cmake --build simulator/build-offline --parallel
```

The existing source tree must also be version 8.3.11. Neither CMake nor the
simulator writes to the firmware LVGL source/configuration.

## Controls

- Left mouse: touch, drag sliders/rollers, click buttons; horizontal drag and
  release navigates (at least 40 logical pixels, predominantly horizontal).
- Left/right arrows: navigate one page per key press, same direction as firmware.
- W/X: tilt along the first IMU axis; A/D: second axis; R: reset tilt.
- Space: toggle the simulated clock between real time and 10× speed.
- S: save `screenshot.bmp` in the current directory. Escape: quit.

The resizable window preserves the square aspect ratio with letterboxing. The
framebuffer is 240×240, enlarged to 720×720 initially. The circular mask is applied
to both presentation and captures; mouse presses outside the circle are rejected.
Lost focus releases the touch. Batched press/release events are delivered
individually to LVGL so quick clicks are preserved. Brightness requests are recorded for assertions;
they do not dim the window or change screenshot colors.

## Automated verification

```sh
ctest --test-dir simulator/build --output-on-failure
```

No window, USB board, running desktop session, or X server is needed. Tests use
SDL's dummy video driver, a deterministic clock and the real firmware page loop.
The integration contract runs each scenario twice and compares exact screenshots.
It also checks committed visual baseline hashes to detect changes across runs.
CTest additionally runs isolated navigation and timer-state regressions, including
precise pause, millis rollover, immediate paused reentry and background expiry.

Artifacts are under `simulator/build/screenshots/`:

- `report.json`: named interaction checks, counts and failures;
- `*.bmp`: native SDL captures, including the circular bezel;
- `*.png`: portable previews generated by the Python test runner.

You can also run `blob_simulator --test --output /tmp/blob-captures` directly. It
writes BMP files and the report; the Python runner adds PNGs and baseline checks.

Coverage includes repeated and reverse swipes, screen identity, slider geometry,
pointer dragging to 5% and 100%, backlight requests, retained brightness, timer
roller callbacks, pointer clicks for start/pause/resume/cancel, paused back/return, the ended
screen with original duration and repeat/back actions, deterministic countdown
and expiry, zero duration, IMU clamping, RGB565 byte order, circular
masking, window resize/letterboxing, SDL mouse gestures and lost-focus release.
Timer duration setup sends real LVGL roller change events; it does not currently
assert the physical pointer mechanics of roller scrolling.

## Intentional visual changes

Inspect generated images first. Then update the checked-in hashes and PNG
references explicitly (from the repository root):

```sh
python3 simulator/tests/test_simulator.py \
  simulator/build/blob_simulator simulator/build/screenshots --update-baselines
ctest --test-dir simulator/build --output-on-failure
```

Review and commit `simulator/tests/visual-baselines.json` and
`simulator/tests/baselines/*.png` with the UI change. Ordinary test runs never
update baselines. Tests run locally by default. The optional GitHub Actions workflow is manual-only
and disabled in the repository; do not enable or run it without an explicit user
request. Pushes and pull requests must not consume Actions minutes. Use a local
Linux container for cross-platform checks when needed.

## Firmware validation and limits

Still run `pio run` after shared-source changes. The simulator does not replace
on-device checks for actual PWM/light output, CST816S gesture timing, SPI/I2C,
USB, RAM outside LVGL, CPU performance, or physical touch sensitivity. Mouse
swipes synthesize the controller's gesture sample; they do not emulate its chip.

The only desktop replacements for headers are the small `Arduino.h` clock/math
shim and the `GUI_Paint.h` RGB565 black constant used by shared UI configuration.
Hardware-facing implementation lives in `src/platform/desktop/` and is guarded
by `BLOB_DESKTOP_SIMULATOR`, so PlatformIO continues to use the native adapter.

## Local larger-Blob experiment

Branch `codex/local-larger-blob` starts from the timer merge. Radius is 50 px
(previously 25 px), with contour wave amplitudes doubled. Face spacing scales
with the radius. The 48-point outline and 16 ms animation timer are unchanged.

Run the interactive preview after saving edits:

```sh
cmake --build simulator/build-release --parallel
./simulator/build-release/blob_simulator
```

Local measurements (Release build):

```sh
./simulator/build-release/blob_shape_benchmark
./simulator/build-release/blob_simulator --benchmark
```

The shape benchmark compares 20,000 varied phases/velocities with the original
formula (maximum permitted coordinate deviation: 1 pixel from floating-point
rounding), then times 100,000 contours. The optimized implementation caches
angular samples and computes six phase-dependent sine/cosine values per contour;
velocity projection replaces atan2 and radial cosine calls. Cache storage costs
about 1.5 KiB of RAM. First-call setup is excluded from the timing comparison.

On this Mac, the contour calculation measured roughly 14–16× faster. This is
**only the contour calculation**, not total animation FPS. Display monitor counts
for 10 simulated seconds were 500 rendered frames in each case: about 4,646 pixels
per frame at radius 25 versus 14,712 at radius 50 (3.17× the RGB565 transfer data).
Desktop end-to-end timings do not establish a speedup and are too small/noisy to
predict the board's performance. The simulator uses a synthetic clock, SDL instead
of SPI, and the Mac CPU instead of RP2040; real frame rate needs a board measurement.
The experiment remains unpushed; it has now been flashed and measured on the board.

### Device transfer measurements

The installed RP2040 SPI library's `transfer(buffer, length)` overload exchanges
bytes individually and overwrites the source with received data. The bulk
`transfer(buffer, nullptr, length)` overload uses transmit-only block writes.
`LCD_1IN28_DisplayArea` now sends each tightly packed rectangular region as one
block, rather than one call per row. The SPI clock remains unchanged.

At radius 50, 9-second serial samples on the connected board measured:

| Transfer path | Rendered FPS | SPI ms per frame |
| --- | --- | --- |
| Original byte-wise transfer | 15–16 | 46–49 |
| Bulk transmit-only transfer | 34–36 | about 12 |

These are on-device LVGL refresh measurements, not desktop extrapolations.
Tilt/contour phase change the dirty area slightly between samples. DMA was also
tried and removed because it did not measurably improve this workload. Normal
firmware builds do not print diagnostics. To repeat the measurement, keep the Blob
page visible and run locally:

```sh
pio run -e waveshare_rp2040_touch_lcd_perf -t upload
pio device monitor -b 115200
```

The optional diagnostics print rendered FPS, average LVGL refresh time, average
SPI flush time, and pixels per frame once per second. Use `pio run -t upload` to
restore the normal build without diagnostics.
